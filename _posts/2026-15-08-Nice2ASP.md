## Problem

The UK National Institute for Health and Care Excellence (NICE) produces guidelines that provide evidence-based recommendations to support clinical care across England and Wales. However, these documents and all other healthcare guidelines are published in natural language form. This presents challenges when converting the guidelines into a computational model that could greatly benefit clinician workflow and patient treatment: imagine a scenario where the doctor is automatically given the recommendations of the guidelines based on the patient's features. Although work has been done to create models for specific diseases, it is a manually intensive process, requiring debate among clinicians. In this work, we provide a possible solution for solving this problem.

## Method

Our work builds off [Ishay et al.](https://arxiv.org/abs/2307.07699), using LLMs to convert these guidelines to Answer Set Programs (ASP). ASP is a declarative logic language that is particularly suited to medical reasoning due to its ability to:

- represent if and else rules with multiple variables
- represent choice options within rules
- represent the logic in a program that can be executed and solved to find possible solution sets to the problem

We complete this translation in three stages, which we define as data-to-knowledge:

1. Constant extraction: prompt the LLM with the relevant guideline to pull out medical terms and define them in a set of predefined clinical categories based on an ontological map.
2. Predicate generation: once we have these constants, use them to define predicates, which are usually verbs, to describe how they interact with each other.
3. Rule generation: give both the extracted constants and generated predicates to generate the rules within ASP.

![Pipeline](/images/NICE2ASP/pipeline.png)
*Approach for automatically converting clinical guidelines to an executable model. The Data-­to-­Knowledge approach uses the NICE guidelines as input and extracts constants, generates predicates and then generates rules in a stepwise manner to build a patient-agnostic executable model. The Knowledge-­to-­Performance approach then takes free-form patient vignettes from which it extracts facts and combines them with the executable model to compute explainable guideline recommendations by means of a reasoning engine (the Clingo ASP solver).*

In order to actually make this program usable, we use the LLM again to extract the patient facts from their report and feed these, along with the program, to Clingo, an ASP solver. We call this Knowledge-to-Performance.

![Translation](/images/NICE2ASP/rule_translation.png)
*During evaluation, the NICE guideline rules, generated ASP rules, and controlled natural language of the generated rule are provided to the reviewers to categorise the ASP translation of the original rule. This same process can be applied again during Knowledge-­to-­Performance for the generated recommendations.*

## Results
We complete this for both the pancreatic cancer and lung cancer diagnosis guidelines and find that our method results in a greater number of correctly translated rules with fewer errors across missed rules, incorrect translations, missed information and hallucinations. Additionally, we tested the Knowledge-to-Performance approach on 20 pancreatic cancer vignettes and found encouraging F1 scores and strong reviewer agreement.

## Discussion and conclusion
This method can be applied to any medical guideline in general, with only slight customisation required. By translating natural language rules to formal logic, we are able to actually solve the program and output the recommendations in a completely explainable way. This could help clinicians such as GPs, who have to deal with many patients throughout the day presenting with non-specific symptoms, as well as NICE themselves in making sure rules across diseases are consistent.
